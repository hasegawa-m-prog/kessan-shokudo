# 決算食堂（仮）

## 1. サービス概要

会社の数字に苦手意識がある外食業界の人が、図解付きの3択クイズでBS（貸借対照表）の基本を学ぶサービスです。
架空の飲食店の取引を題材に、取引前後の図と短い解説で、資産・負債・純資産の変化を理解します。
ログインすると回答履歴が残り、間違えた問題を後から復習できます。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

2026年に入り、勤務先の公開IR情報をWebで見ても、数字の意味や読み方がわからず、「自分の会社の数字なのに、このままではまずい」と感じました。

当初は企業の数値比較や株価予想を考えていましたが、その前に、取引と会社の数字の関係を理解する基礎が必要だと考え直しました。

例えば、厨房設備を購入したときに、現金と設備がそれぞれどう変わるのかを図で確認できれば、自分にも学び始めやすいのではないかと思いました。

### 2-2. なぜそれが「気になった」のか

自分が働く会社だからこそ、数字を理解できない状態をそのままにしたくなかったためです。

用語を読むだけでなく、身近な取引について自分で考え、図と解説で確かめることで、少しずつ理解する手応えを得たいと考えています。

## 3. 課題の整理

### 3-1. 表に見えている困りごと

資産・負債・純資産という言葉を見ても、店舗で行う取引と結び付かず、BSの読み方がわかりません。

### 3-2. 本当に解決したい課題は何か

- なぜ困るのか：会社の数字を見ても、何を表しているか説明できないからです。
- なぜ説明できないのか：取引によって、どの項目がどう変わるか理解できていないからです。
- なぜ理解が進まないのか：文章や用語を読むだけで終わり、具体的な場面で考えて確かめる機会が少ないからです。

本当に解決したいのは、会社の数字を理解したいのに、日々の取引と数字が結び付かず、学び始める手応えを得られないことです。

本サービスでは、その入口としてBSの基本的な変化に学習範囲を絞ります。IR全体の分析までを扱うものではありません。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

外食業界で働き、会社の数字に関心はあるものの、簿記を体系的に学んだ経験が少ない会計初心者です。

- 年齢：40代前後。自分に近い人を起点に、困りごとを具体的に考えるための設定です。
- 生活・状況：自社の決算や仕事で会社の数字に触れた際、会計用語で読む手が止まる人です。
- 利用環境：休憩中や帰宅後にスマートフォンで利用することを想定しています。
- 必要としている体験：長い教材を読む前に、短い問題と図解で基本的な関係を確かめられることです。

### 4-2. 自分とユーザーの距離

自分自身が想定ユーザーに近い立場です。

会社の数字を理解したい一方で、会計の用語と具体的な取引が結び付かないという、自分の困りごとから考えました。

自分以外の人にも役立つかは、開発後の試用を通じて確認します。

### 4-3. 実際に使われる可能性について

#### 試用を依頼する対象

最初に自分自身で操作を確認します。
その後、外食業界で働き、会計の学習経験が少ない知人2〜3名を目安に試用を依頼する予定です。

次の条件に近い人を優先します。

- 外食業界で働く40代前後の人。
- 自社の決算や会社の数字に関心がある人。
- 簿記の学習経験が少なく、BSの用語や読み方に苦手意識がある人。

依頼時に仕事内容・会計学習経験・数字について困った経験を確認し、想定ユーザーに近い人の意見を集めます。

想定ユーザー以外にも操作性の確認を依頼する場合がありますが、学習上の需要については、想定ユーザーの意見と分けて整理します。

#### 利用が想定される場面

- 自社のIRを開き、資産・負債などの用語で読む手が止まったとき。
- 仕事で見聞きする取引が、会社の数字にどう表れるか知りたいとき。
- 以前間違えた問題を、短い時間で復習したいとき。

公開IRやWebの会計解説を置き換えるのではなく、それらを読むための基礎学習を補う位置付けです。

#### 試用で確認すること

1. 補助説明なしで、回答と解説の確認まで進められるか。
2. 解説を読んだ後に、何が増減し、なぜそうなるかを自分の言葉で説明できるか。
3. 数字や場面を変えた確認問題でも、同じ考え方を使えるか。
4. 次の問題や、間違えた問題の復習に取り組みたいか。その理由は何か。
5. 普段使う教材がある場合、それと比べてわかりやすかった点・わかりにくかった点は何か。

正解数や楽しさの感想だけでなく、説明できた内容と、操作・理解につまずいた箇所を記録し、改善に活かします。

### 4-4. 利用開始から継続までのイメージ

1. 会社の数字が気になったとき、知人からの紹介などでサービスを知ります。
2. 登録せずに基本問題を試し、図解と解説を確認します。
3. 後から復習したいと感じたら、ユーザー登録・ログインをします。
4. ログイン後にクイズを開始し、回答履歴を残します。
5. 後日、履歴から間違えた問題を選び、再挑戦します。

ゲストで解いた回答は履歴に保存せず、登録後への引き継ぎも行いません。
履歴を残すには開始前のログインが必要であることを案内します。

#### 補助的な比較対象

日本商工会議所「簿記初級」のサンプル問題は、学習範囲を考えるための補助的な比較対象とします。
アプリとしての操作体験とは分けて扱います。

#### 調査からわかったこと

短時間学習、クイズ、解説、復習は、既存サービスにもある要素です。
「身近な例を使う」ことだけで差別化できるとも考えていません。

本サービスでは、対象と範囲を絞り、「飲食店の取引を読む→変化を考える→同じ店舗のBSを前後で見比べる」という体験に重点を置きます。

### 5-2. それでも自分が作りたい理由

自分が最初に解決したいのは、仕訳を速く書くことや試験に合格することよりも、会社の数字が何を表すかわからないという状態です。

例えば、現金で厨房設備を買ったときに、現金は減っても資産合計は変わらないという関係を、仕事で身近な場面と結び付けて理解したいと考えています。

既存サービスを否定するのではなく、自分には取引前後の図を比べる学び方が入口になるのではないか、という仮説から企画しています。
その学びやすさを、開発後の試用で確認します。

### 5-3. 差別化を体験価値で表現する

外食業界の会計初心者が、店舗で行う取引とBSの変化を結び付けられる体験を目指します。

#### 学習の流れ

1. 架空の飲食店の取引と、取引前のBSを見る。
2. どの項目がどう変わるかを3択で考える。
3. 回答後に、取引前・取引後のBSを同じ縮尺で比較する。
4. 増減した項目と、変わらない項目を確認する。
5. 変化の理由と、間違えやすい点を短い解説で読む。

基本問題は一つの取引、応用問題は少数の取引を扱います。
応用問題でも図は開始前と全取引終了後の2つにし、途中の変化は文章で説明します。

#### 図解の見せ方

- 比較単位は企業同士ではなく、同じ店舗の取引前後とします。
- 左側に資産、右側に負債・純資産を配置します。
- 単位を万円に統一し、前後で項目順・色・金額に対する縮尺をそろえます。
- 前後の図の高さをそれぞれ100％にそろえず、合計額の変化も読み取れるようにします。
- 増減は色だけでなく、「現金 −100万円」などの文字で示します。
- スマートフォンでは前後の図を縦に並べ、横スクロールを不要にします。

#### 具体例

現金1,000万円、負債0万円、純資産1,000万円の状態で、厨房設備を現金100万円で購入したとします。

- 現金：1,000万円 → 900万円
- 設備：0万円 → 100万円
- 資産合計：1,000万円 → 1,000万円
- 負債：0万円 → 0万円
- 純資産：1,000万円 → 1,000万円

解説では「現金は減ったが、同額の設備が増えたため、購入直後の資産合計は変わらない」と説明します。

税金・諸費用・減価償却などを考慮しない簡略例であることを明記します。

#### 間違えた後の体験

正解の選択肢だけでなく、取引前後の図と、間違えやすい考え方への説明を表示します。

上の例では、「現金が減ったので資産合計も減る」と考えやすいため、「現金以外に増えた資産はないか」に注目する説明を付けます。

正解・不正解にかかわらず、同じ確認済みの図と固定解説を表示します。選択肢ごとの個別解説生成は行いません。

#### 検証したい価値

飲食店の取引、同じ縮尺の前後比較、変わらない項目も含めた説明を組み合わせることで、仕訳をまだ書けない人でも、BSの変化を説明しやすくなることを目指します。

他サービスに同様の表現がないとは断定せず、この組み合わせを本サービスの設計上の重点として試用で検証します。

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

- 行動の変化：取引を見て、どの項目が変わるかを考え、解説で確かめる。
- 気持ちの変化：「数字はわからない」から「この変化なら説明できる」と感じる。
- 考え方の変化：現金の増減だけでなく、他の資産や負債との関係にも目を向ける。

### 6-2. 価値を一文で表す

外食業界の会計初心者が、身近な取引のクイズと前後の図解を通じて、BSの基本的な変化を自分の言葉で説明する練習ができるサービスです。

## 7. このアプリで実現すること

### MVPで作る機能

#### ① 図解付き3択クイズ

- 基本・応用の難易度を選択します。
- 選んだ難易度から、1回5問をランダムに出題します。
- 同じ回の中では問題を重複させません。
- 基本は一つの取引、応用は少数の取引による変化を扱います。
- 問題には、取引の文章と取引前のBSを表示します。
- ゲストでも利用できます。

初期の問題数は基本10問・応用5問を目安とします。
応用が5問の段階では毎回同じ問題群になるため、ランダム出題だけで飽きを防げるとは考えていません。

必要な理由：用語を読むだけでなく、自分で考えて理解を確かめるためです。

#### ② 正誤判定・解説・結果表示

- 回答確定後に、正誤・取引前後のBS・短い解説を表示します。
- 前後の図は同じ項目順・色・縮尺を使います。
- 増減額と、変わらない項目を確認できるようにします。
- 解説には、何が変わったか・理由・間違えやすい点を記載します。
- 応用問題は、取引の順に文章で説明し、図は開始前と全取引終了後を表示します。
- 5問終了後に正解数と各問の結果を表示します。
- 回答確定後の変更はできず、再挑戦は別の回答として扱います。

図解は共通テンプレートに問題ごとの数値を当てはめます。
正解・不正解にかかわらず、同じ確認済みの図解と固定解説を表示します。

必要な理由：正解を知るだけでなく、取引とBSの変化を結び付けるためです。

#### ③ ユーザー登録・ログイン・回答履歴・復習

- ユーザー登録・ログイン・ログアウトができます。
- ログインして開始したクイズの回答を、ユーザーにひも付けてDBへ保存します。
- 問題、選んだ回答、正誤、回答日時を履歴で確認できます。
- 過去に間違えた問題を、重複をまとめた一覧から選び、1問ずつ復習できます。
- 再挑戦の結果も保存し、過去の回答と見比べられます。
- 復習で正解した後も、過去に間違えた問題として一覧に残します。

ゲストの回答は履歴へ保存せず、登録後への引き継ぎも行いません。

必要な理由：自分がつまずいた問題を後から探し、再挑戦できるようにするためです。

### 問題と解説の準備

- 架空の飲食店の借入、設備購入、借入金の元本返済などを題材にします。
- AIは問題案の下書きにのみ使い、会計処理と数値を開発者が確認してから登録します。
- 正解が一つに定まること、図と解説が一致することを確認します。
- 問題ごとに確認に使った資料と確認日を管理します。
- 初期はseedデータなどで登録し、問題管理専用の画面は設けません。

MVPはクイズ・解説・回答履歴と復習に限定し、実在企業のデータ取得・更新や、利用中のAIによる問題生成は行いません。

### 本リリースに向けた方針

試用でわかった課題をもとに、問題文・図解・復習の使いやすさを改善します。
追加機能は現時点で約束せず、必要性と開発期間を踏まえて判断します。

## 8. このアプリの懸念点とその対策

### 懸念点①：問題や解説が間違っている

- 問題：誤った内容を学習してしまうことです。
- 対策：AIの出力をそのまま公開せず、参考資料・計算・図・選択肢を確認します。確認できない問題は公開しません。
- 注意点：BSの左右が一致するだけでは会計処理の正しさを保証できないため、取引の意味も確認します。

### 懸念点②：答えを覚えるだけになる

- 問題：同じ問題の正解位置や数字だけを覚えてしまうことです。
- 対策：少数でも異なる取引を扱い、理由を説明できるかを試用で確かめます。問題追加は試用結果に応じて判断します。

### 懸念点③：簡略例を実際の決算と混同する

- 問題：学習用に省略した条件が、実務でもそのまま成り立つと誤解されることです。
- 対策：架空の学習用データであることと、税金・利息・減価償却などの扱いを問題ごとに明記します。

### 懸念点④：回答履歴の保存やアクセス制御に不備が出る

- 問題：回答の重複登録や、他のユーザーの履歴へのアクセスです。
- 対策：サーバー側の認証・所有者確認と、DBの制約で防ぎます。ゲストとログイン済みの保存動作を分けてテストします。

### 懸念点⑤：問題の修正で過去の履歴と食い違う

- 問題：正解や文章を書き換えると、過去の回答が何に対するものか不明になることです。
- 対策：公開後に内容を改訂する場合は新しい問題として登録し、旧問題は新規出題・復習の対象から外します。履歴には旧問題と当時の判定を残し、改訂済みと表示します。誤りを修正した場合は訂正内容も案内します。

## 9. 今後の展開・発展の方向性

- 学習内容：試用で説明しにくかった取引や、誤解が多かった箇所を優先して改善します。
- UI：1画面の情報量を抑え、大きな選択肢と読みやすい図解にします。
- 継続利用：正解数だけでなく、過去の誤答と再挑戦の結果を見比べられることで、学習の手応えにつなげます。
- 運用：共通の図解形式を再利用し、問題追加・修正の負担を抑えます。

問題数や機能数を増やすこと自体を目的にせず、理解しやすさと復習したくなるかを確認しながら改善します。

## 10. 技術スタック

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails、ERB。
- 画面：HTML・CSS・SVG。必要な画面操作にJavaScriptを使用します。
- DB：PostgreSQL。ユーザー、問題、選択肢、クイズの実施記録、回答履歴を保存します。
- 認証：学習済みのRailsの認証方式を基本とし、使用バージョンとの適合性を確認して採用します。
- テスト：RSpec。
- 問題登録：seedデータなどのファイルから登録します。
- デプロイ：Renderを候補とし、構成・費用を確認して決定します。
- 外部API：MVPの動作には使用しません。

永続的な回答履歴はDBに保存し、localStorageは使用しません。
ゲストの進行状態は一時的なセッションとして扱い、学習履歴には残しません。

### 10-2. 技術選定の比較検討

| 候補 | 方針 | 理由 |
| --- | --- | --- |
| Rails＋ERB | 採用予定 | 学習済みの構成を活かし、画面とサーバーを一体で実装するため |
| React＋Rails API | MVPでは不採用 | 構成を分ける負担を増やさないため |
| PostgreSQLへの履歴保存 | 採用予定 | ログイン後に自分の履歴を見返し、復習するため |
| seedデータ等での問題登録 | 採用予定 | 初期の問題を管理画面なしで登録するため |
| 共通のHTML・CSS・SVG図解 | 採用予定 | 同じ表現形式を再利用し、制作負担を抑えるため |
| 確認済みの固定解説 | 採用予定 | 内容を確認した説明を提供するため |
| 利用中のAI生成 | MVPでは不採用 | 正確性の確認、待ち時間、API費用への対応を増やさないため |

- 挑戦したい点：ランダム出題、ユーザーごとの履歴と復習、スマートフォン向けのBS図解です。
- 不安な点：二重登録防止、アクセス制御、問題と履歴の整合性です。

### 10-3. キャッチアップ不足の懸念

ランダム出題、ユーザーごとの回答履歴、BS図解の表示には、追加の調査と学習が必要です。

最初に「1問を表示する→回答する→正誤と解説を表示する」を試作します。
その後、5問の出題、ログインと回答保存、履歴と復習の順に実装します。
図解は共通テンプレートを使い、問題ごとの数値を当てはめて表示します。

次の点をテストします。

- 選んだ難易度から、同じ回の中で重複せずに5問出題されること。
- 出題可能な問題が5問未満の場合は、開始できない旨を案内すること。
- 正誤をサーバー側で判定し、5問終了後に正解数を表示できること。
- ログインしたユーザーの回答履歴がDBに保存され、再ログイン後も確認できること。
- ゲストの回答は履歴に保存されず、登録後にも引き継がれないこと。
- 二重送信で同じ回答が重複登録されないこと。
- 他のユーザーの回答履歴を閲覧・変更できないこと。
- 間違えた問題を選んで1問ずつ復習でき、再挑戦の結果も保存されること。
- 問題の改訂後も、過去に回答した問題と結果の対応が保たれること。
- 改訂前の問題は新規出題・復習に含まれず、履歴で改訂済みと確認できること。
- 取引前後のBSが同じ単位・縮尺で表示され、増減額と登録データが一致すること。
- 取引前後それぞれで、資産合計と負債・純資産合計が一致すること。
- スマートフォンでも、問題・選択肢・前後の図・解説を横スクロールせずに確認できること。

使用技術のサポート状況・ライセンス・費用は、採用前に確認します。
調査や学習に必要な時間も、開発の見積もりに含めます。
