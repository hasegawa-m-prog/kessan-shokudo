# 決算食堂（仮）

## 1. サービス概要

外食企業の株価を予想し、結果を振り返りながら、株や会社の数字の読み方を学ぶサービスです。
IRを見ても数字の意味がわからない外食業界の投資初心者に、BS（貸借対照表）の図解比較とキャラクターによる解説を提供します。
予想する楽しさを入口に、ROE・ROIC・WACCやキャッシュフローなどを、予想の根拠として考えられるようになることを目指します。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

- いつ：2026年に入り、自社の数値を理解できていないことを問題だと感じるようになりました。
- どんな状況で：私はファミリーレストランで働いています。Webで公開されているIR情報を中心に自社の数値を見ていますが、数字の見方がわからず、その数値が良いのか悪いのか判断できませんでした。
- どんな気持ちになったか：「自分の会社の数値なのに、良いのか悪いのかもわからない。このままではまずい」と感じました。普段からアプリで数字に触れ、同業企業を比較しながら、株や会社の数値が読めるようになりたいと思いました。

ただ数字を勉強するだけでなく、「どの会社の株価が上がりそうか」を予想する要素がある方が、自分がやってみたいと思えます。そこで、株価予想とキャラクターの解説を入口に、楽しみながら企業の数字を学ぶアプリを考えました。

また、業種が変わるとBSの図解の形が大きく変わる点にも面白さを感じています。飲食企業だけでなく、他の業種と比べて「なぜこんなに違うのか」を考える体験も取り入れたいです。

### 2-2. なぜそれが「気になった」のか

知らない会社ではなく、自分が働いている会社の数字だからこそ、見ても良し悪しがわからない状態を、そのままにしたくないと思いました。
Webで情報を手に入れられても、それを理解して判断することは別だと感じています。数字を眺めるだけでなく、同業企業と比較し、自分なりに会社の状況を考えられるようになりたいです。
また、学習だけを目的にするよりも、予想や少し笑えるキャラクターの説明を通じて、楽しみながら数字に触れられることを大切にしたいです。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

Webで自社のIR情報を見ても、数字の見方がわからず、良い状態なのか悪い状態なのか判断できないことです。

### 3-2. 本当に解決したい課題は何か

- なぜ困るのか：自分の会社の数字を見ても、良いのか悪いのか判断できず、会社の状況を理解できているという手応えがないからです。
- なぜ判断できないのか：数字の意味や、何と比較して考えればよいのかがわからないからです。
- なぜわからない状態が続くのか：WebでIR情報を見つけることはできても、読むだけでは理解につながらず、繰り返し比較して身につける学び方が必要だと考えているからです。

→ 本当に解決したい課題：身近な会社の数字を理解したいのに、見ても判断できず、「わからないままでいる」ことに不安を感じていることです。株価予想と振り返りをきっかけに、数字を自分で読み解く手応えを得られるようにしたいです。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

まずは自分自身のように、外食業界で働き、同業企業の株に興味があるものの、IRの数字を読むことに慣れていない人を想定します。

年齢設定：

- 年齢：40代を中心に想定します。
- 理由：自分に近い年代と状況に絞ることで、身近な企業を題材に学びたいという困りごとを具体的に考えやすいためです。他の年代より需要が高いと確認したわけではなく、年齢よりも外食業界への馴染みと投資学習の状況を重視します。

生活・状況設定：

- 生活・状況：外食業界で働き、自社や競合企業の業績・株価が気になったときに、短い時間で比較してみたい人です。
- 理由：知っている企業を選ぶところから始め、数値と解説を同じ画面で確認できるようにすることで、読むべき項目を探す迷いを減らします。

環境設定：

- 環境：スマートフォンで手軽に利用したく、複数のIR資料を開いたり、数値を転記したりする作業は避けたい人です。
- 理由：アプリ側で対象企業の公開情報を整理し、利用者は企業や気になる指標を選ぶだけで比較できるようにします。

### 4-2. 自分とユーザーの距離

- 自分自身

→ IRを見ても株や会社の数字がわからず、比較しながら読めるようになりたいという、自分の困りごとから考えたためです。

### 4-3. 実際に使われる可能性について(需要・存在確認)

- まず最初に使ってくれそうな人：自分自身です。その後、外食業界で働く知人などに試してもらいたいと考えています。協力者はこれから募集します。
- どんな場面で思い出すか：自社や競合の決算・株価が気になり、「どちらの会社に期待できそうか」と比較したくなったときです。
- 代わりに使っているもの：Webで公開されている自社のIR情報を中心に見ています。
- 置き換えてまで使う理由：資料を読むだけではわからなかった数字を、企業比較と短い解説で理解し、自分の予想を残して結果まで振り返れることです。IR自体を置き換えるのではなく、IRを読めるようになる入口を作ります。

試作後に協力者から、迷った操作、理解できなかった説明、また使いたい理由を聞いて改善します。自分以外の需要はまだ確認できていません。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

- 知る・思い出すきっかけ：外食企業の決算や株価が気になったときに、知人への紹介や共有リンクからアクセスしてもらいます。
- 最初の一歩：登録せずに2社を選び、指標と株価シナリオ、キャラクターの解説を確認します。予想を保存するときに登録します。
- 利用の流れ：企業を選ぶ→BSの図とキャッシュフロー・指標を比べる→解説で違いを知る→3か月後の値動きを予想して理由を残す→結果を確認する、という流れです。
- 継続する理由：自分の予想がどうなったかを確認し、当たった場合も外れた場合も、次の予想に活かせるためです。結果を待つ間は、別の企業の比較や指標の復習ができます。

企業向けの業務サービスではなく、個人の学習・仮想投資を想定します。勤務先の社内資料や未公表情報は登録しません。

本リリースでは「異業種くらべ」から、飲食企業と他業種の企業のBSを並べられるようにします。「どちらが在庫の割合が大きそうか」などを予想してから図と解説を見ます。株価を予想せず、会社の仕組みを比べるだけでも楽しめる入口にします。

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

- サービス名：バフェット・コードBusiness
- URL：https://business.buffett-code.com/
- どんなことができるか：企業の財務・経営指標の比較、過去の業績推移の確認、IR情報の検索などができます。

公開ページの調査内容です。有料機能の操作検証は行っていません。株価予想・仮想投資サービスとの比較も、今後の調査対象とします。

### 5-2. それでも自分が作りたい理由

WebのIR情報で数字を確認できても、その数値が良いのか悪いのか判断できないという点が、自分にとっての困りごとでした。情報がないのではなく、情報を見ても読み解けないところに、自分が求める体験とのズレがあります。
数値を確認するだけでなく、「この会社の株は上がりそうか」を予想し、その理由と結果を振り返る形なら、自分が使ってみたいと思えます。
そのため、まずは身近な外食企業を入口に、キャラクターの解説を読みながら予想できるサービスを作りたいです。さらに異業種のBSと比べ、会社による資産や資金調達の構成の違いを図から発見する体験へ広げたいです。

バフェット・コードを実際に使って感じた不満はまだ確認できていません。既存サービスに同様の体験がないとは断定せず、実際に操作して、自分が求める学び方との違いを確かめます。

### 5-3. 差別化を「体験価値」で表現する

- 私のアプリの差別化ポイント：外食業界で働く投資初心者が、身近な企業の株価が気になった瞬間に、企業を選ぶだけで比較と解説を確認し、理由を持って予想する練習ができることです。

予想を保存して終わりではなく、結果を見て「自分は何を根拠に考えたか」まで振り返る体験を目指します。これは現時点での差別化仮説です。

本リリースでは、馴染みのある飲食企業と他業種のBSを比べ、「会社によって、お金の持ち方・集め方がこんなに違う」と気づける体験も提供します。異業種の優劣を決めるのではなく、違いの理由を楽しむことを目的にします。

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

- 行動の変化：会社名や印象だけで選ぶのではなく、指標を比較して予想の理由を残し、結果を振り返るようになることを目指します。
- 気持ちの変化：「数字がわからない」から、「この数字なら意味を説明できる」という手応えを持てるようになることを目指します。
- 考え方の変化：「利益が増えれば必ず株価が上がる」ではなく、株価に織り込まれた期待や、資本効率・現金の動きも考えるようになることを目指します。

### 6-2. 価値を一文で表す

このサービスは、身近な外食企業の株に興味がある投資初心者が、株価予想を楽しみながら、会社の数値を読み、自分なりの根拠を持って考えられるようになるサービスです。

## 7. このアプリで実現すること

### MVPで作る機能

- 外食企業約8社の一覧と2社比較。過去3年分を目標とし、最初に2社・1年分でデータ取得と表示を検証します。
- ROE、ROIC、推定WACCとその差、営業利益率、EPS・PER・PBRの表示と用語解説。算出できない指標は理由とともに表示します。
- 営業・投資・財務キャッシュフローと、算出可能な企業のCCCの表示・解説。
- 飲食企業同士のBS図解比較。各社の資産と負債・純資産を左右に配置し、現預金・営業債権・棚卸資産・有形固定資産・その他資産、負債・純資産などの構成を色分けします。総資産を100％とした構成比と実額を切り替え、各項目の意味を確認できるようにします。
- 弱気・基本・強気の条件付き株価シナリオと、選択したシナリオの株価変化率順のランキング。
- 検証済みデータを使ったAI解説の事前生成・管理者確認・保存。静止画キャラクターとテキストで表示します。
- ユーザー登録・ログイン、3か月後の株価予想と理由の保存、期限後の答え合わせ。
- 仮想投資のROIの表示。初期は配当・手数料・税を含まない、投資期間中の価格収益率として扱います。
- 理解度チェックと学習履歴・メモの保存。
- 数値の出典、対象期間、更新日、推定条件の表示。

対象候補はジョイフル、サイゼリヤ、すかいらーくHD、ゼンショーHD、ロイヤルHD、SRS HD、木曽路、王将フードサービスです。すき家とココスはゼンショーグループとして扱い、ブランドと上場企業を区別します。

株価シナリオは予想EPSと想定PERによる条件付きの評価額です。財務指標だけで将来の市場価格が決まるとは扱いません。株価データの公開利用条件・取得方法は未選定であり、実装前に確認する必要があります。

### 本リリースで作る機能

- 飲食以外とのBS図解比較「異業種くらべ」。まずは製造業・小売業・ITサービス業を候補に、データを確認できる企業を各1社程度追加します。対象企業は未選定です。複数事業を持つ会社は事業構成も併記し、1社の特徴を業種全体の特徴と断定しません。
- BSの違いを当てるミニクイズと、キャラクターによる根拠付き解説。「在庫の割合が大きいのはどちら？」などの問いから、商売の仕組みを学びます。
- オリジナル3Dアバター1体の表示と簡単な動き。
- 質問ボタンによる追加解説と、解説の読み上げ。
- 間違えた問題や学習履歴に応じた復習機能。
- 決算更新時に、以前の予想や企業の状態と比較できる機能。

リアルタイム音声対話はさらに先の拡張とし、証券口座連携・実際の売買注文・機械学習による短期株価予測は初期開発に含めません。

異業種の追加対象はBS比較と学習機能に限定し、株価予想・ランキングの対象は当初の外食企業から広げません。BSはある時点の残高、キャッシュフローは一定期間の現金の動きとして、別の図で表示します。

## 8. このアプリの懸念点とその対策

### 懸念点①：株価・財務データの取得と利用条件

- 何が問題になりそうか：必要な株価データを公開アプリで使えず、予想と答え合わせが成立しない可能性があります。
- なぜそう思うか：IRだけでは市場データが揃わず、データ提供元ごとに表示・保存・再配布等の条件があるためです。
- そのために考えている対策：対象企業を絞って、利用条件と取得方法を最初に検証します。解決しない間は架空データで技術検証し、実データのサービスを完成したとは扱いません。

### 懸念点②：数字やAI解説を誤って受け取られる

- 何が問題になりそうか：会計条件の異なる企業を単純比較したり、AIの説明を確実な株価予測として受け取られたりするおそれがあります。
- なぜそう思うか：企業ごとに決算期や事業構成が異なり、WACCには推定も必要で、AIが根拠のない説明をする可能性があるためです。
- そのために考えている対策：計算はプログラムで行い、実績・推定・仮定と出典を区別します。AI解説は確認して保存し、上昇理由だけでなくリスクも示します。予想時点の情報を保存し、後から結果に合わせて書き換えません。

### 懸念点③：完成までの負担と運用費用

- 何が問題になりそうか：データ整備・AI・3D・音声を同時に実装すると、開発期間や費用が膨らむ可能性があります。
- なぜそう思うか：新しく学ぶ要素が多く、まだ作業時間を正確に見積もれていないためです。
- そのために考えている対策：2社の比較と予想保存を先に試作します。AI解説は閲覧ごとに生成せず再利用し、利用上限を設けます。3D・音声は段階を分けて追加します。

### 懸念点④：異業種比較による誤解とデータ整備の増加

- 何が問題になりそうか：BSの形だけで良い会社・悪い会社を決めたり、対象業種を増やしすぎて実装が遅れたりする可能性があります。
- なぜそう思うか：資産構成は事業や会計処理によって異なり、企業間で科目の整理も必要になるためです。
- そのために考えている対策：異業種比較は本リリースで少数の企業から始め、優劣の点数を付けません。決算日、会計基準、連結・単体を表示し、対応づけた科目と出典を管理します。資産合計と負債・純資産合計の一致を検証し、欠損を0として描画しません。純資産が負の場合などは通常の100％積み上げ図で隠さず、別表示と説明を用意します。

### 懸念点⑤：一度使って終わる・学習につながらない

- 何が問題になりそうか：キャラクターを見て終わり、数字の理解や継続利用につながらない可能性があります。
- なぜそう思うか：決算情報は毎日更新されず、3か月後の結果を待つだけでは再訪の動機が弱いためです。
- そのために考えている対策：待っている間に別の企業の比較や復習をできるようにします。協力者に、利用前後で数字を説明できるか、再訪したいかを確認します。

## 9. 今後の展開・発展の方向性

### 今考えている発展案

- 機能追加の方向性：予想履歴と結果を蓄積し、自分がどの指標を重視したときに予想が外れたかを振り返れるようにします。異業種くらべはデータを確認しながら対象を増やし、BSの違いと商売の仕組みを結びつけるテーマを追加します。将来的にはWACCを使った企業価値評価や音声対話も検討します。
- UI・体験の改善：BS図の構成比・実額の切り替えや、項目をタップして意味を確認できる画面を用意します。3Dアバターの説明と合わせて、図から違いを発見できる体験を目指します。
- 機能以外の工夫：決算の更新に合わせて短い学習テーマを用意し、知人などと同じ企業を比較して読み方を話せる機会を作りたいです。

続けることで、当たった・外れたという結果だけでなく、自分の考え方の変化を確認できるサービスを目指します。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails。画面はERBとHotwire/Stimulusを使う予定です。
- DB：PostgreSQL。
- デプロイ先：Renderを候補にしています。必要な構成と料金を確認して確定します。
- 使用予定ライブラリ：Chart.js（グラフ）、RSpec（テスト）。本リリースでThree.js（3D表示）を検討します。
- 外部API：AI解説用のLLM APIと株価データ提供サービス。提供元は、費用・利用条件・対応データを確認して選定します。

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| Rails＋ERB＋Hotwire | 採用予定 | カリキュラムで扱った技術を活かし、画面とサーバーを一つのアプリで管理するため |
| React＋Rails API | MVPでは不採用 | フロントとバックエンドを分ける負担を増やさず、比較と予想の体験を先に完成させるため |
| 確認済みデータのCSV取り込み | 採用予定 | 各社の単位・科目・出典を確認しながら、対象企業を絞って整備できるため |
| IR資料の全自動抽出 | MVPでは不採用 | PDFの形式差や誤抽出への対応まで含めると作業範囲が広がるため |
| AI解説の事前生成・保存 | 採用予定 | 説明の確認と利用料金の管理をしやすくするため |
| リアルタイム音声対話 | MVPでは不採用 | 音声処理と継続的なAPI費用が必要になるため |

- 今回チャレンジしたい点：財務データを比較しやすく整理し、計算結果をAIのわかりやすい説明につなげることです。本リリースでは3Dアバターにも取り組みたいです。
- 不安な点：株価データの利用条件、財務指標の計算条件を揃える作業、AI解説の正確さ、3Dの学習時間です。

### 10-3.キャッチアップ不足の懸念

AI連携・財務データ整備・3D表示には、まだ調査や学習が必要です。そのため、完成までの作業量やIssueの見積もりが不確かになることを懸念しています。

最初に2社・1年分のデータで、取り込み・比較・株価シナリオ・予想保存までの小さな検証を行い、調査時間と実装時間を把握します。
AIが使えない場合も確認済みの定型文を表示できるようにし、まず基本の流れを成立させます。
Reactへの移行は前提とせず、3Dや音声も単独で試作してから組み込みます。使用するライブラリのサポート状況とライセンスは、実装前に確認します。
