# 決算食堂（仮）

## 1. サービス概要

会計初心者が、関心のある業種を選び、架空の会社を題材にした3択クイズでBS（貸借対照表）の基本を学ぶサービスです。
会社ごとの資産構成や取引前後の変化を図で見比べ、数字の意味を短い解説で確認します。
ログインすると回答履歴が残り、間違えた問題を復習できます。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

勤務先の公開IR情報を見ても数字の意味がわからず、「自分の会社の数字なのに、このままではまずい」と感じたことがきっかけです。

当初は企業比較や株価予想を考えていましたが、その前に、会社の仕事と数字の関係を理解する基礎が必要だと考えました。

業種によって在庫や設備などの構成が異なる点にも興味があり、図を見比べながら学べる形にしたいと考えています。

### 2-2. なぜそれが気になったのか

用語を覚えるだけでなく、自分の仕事や関心のある会社と結び付けて理解したいためです。
問題を解き、図と解説で確かめることで、少しずつ理解する手応えを得たいと考えています。

## 3. 課題の整理

### 3-1. 表に見えている困りごと

資産・負債・純資産という言葉を見ても、会社の仕事や取引と結び付かず、BSのどこに注目すればよいかわかりません。

### 3-2. 本当に解決したい課題

会社の数字を理解したいのに、用語を読むだけで終わり、具体的な場面で考えて確かめる機会が少ないことです。

本サービスでは、BSの構成と基本的な取引による変化に範囲を絞り、学び始める入口を作ります。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

自分が働く会社や関心のある業種の数字を理解したいものの、簿記を体系的に学んだ経験が少ない会計初心者です。
休憩中や帰宅後に、スマートフォンで短時間利用する場面を想定しています。

外食業界での自分の経験が出発点ですが、BSの基本は他業界にも共通するため、利用者を外食業界に限定しません。
小売業・製造業・サービス業から、自分の仕事や関心に合わせて学習の入口を選べるようにします。

### 4-2. 自分とユーザーの距離

自分自身が、会社の数字に関心はある一方、会計用語と具体的な仕事が結び付かないと感じている立場です。
自分だけでなく、同じような会計初心者にも役立つかを試用で確認します。

### 4-3. 試用を依頼する対象と確認方法

開発後は、会社の数字に関心があり、会計学習経験の少ない同僚・知人2〜3名を目安に試用を依頼します。

仕事内容・勤務業種・会計学習経験を確認し、可能であれば異なる業種の人にも依頼します。
会計経験のある人から操作性の意見をもらう場合は、初心者の学習上の意見と分けて整理します。

確認する内容は次のとおりです。

- 業種選択から5問の回答・解説確認まで、迷わず操作できるか。
- 図を見て、構成の違いや取引による変化の理由を説明できるか。
- 自分の仕事や関心のある業種を選ぶことが、学習のきっかけになるか。
- 別の業種への挑戦や、間違えた問題の復習をしたいと感じるか。

感想だけでなく、説明できた内容やつまずいた箇所を記録し、改善に活かします。

### 4-4. 利用開始から継続までのイメージ

1. 会社の数字に関心を持ち、紹介などを通じてサービスを知ります。
2. 学びたい業種を選び、登録せずに5問を試します。
3. 復習したいと感じたら、ユーザー登録・ログインをします。
4. ログイン後の回答を履歴に残し、後日、別の業種への挑戦や復習を行います。

ゲストの回答は履歴に保存せず、履歴を残す場合は開始前にログインするよう案内します。

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

### 5-2. それでも自分が作りたい理由

自分が最初に解決したいのは、仕訳を速く書くことよりも、会社の数字が何を表しているかわからないという状態です。

関心のある業種を選び、在庫や設備などを仕事と結び付けて図で考える学び方が、学習の入口になるのではないかと考えています。

### 5-3. 差別化を体験価値で表現する

「関心のある業種を選ぶ→2つのBSを見比べて考える→図と解説で理由を確かめる」という体験に重点を置きます。

比較は次の2種類です。

- 会社同士の比較：条件を示した架空の2社について、在庫や設備の金額・割合を考えます。
- 取引前後の比較：同じ会社について、設備購入や借入による変化を考えます。

例えば、小売会社と在庫を持たないサービス会社の例で、在庫の割合を比較します。
ただし、「その業種なら必ず同じ構成になる」「在庫が多いほど優秀」とは説明しません。

取引前後の問題では、設備を現金100万円で購入した場合に、現金が100万円減り、設備が100万円増え、購入直後の資産合計は変わらないことを示します。
税金や減価償却などを省略した例であることも明記します。

図は同じ問題内で単位・色・金額に対する縮尺をそろえ、増減や割合を文字でも示します。
スマートフォンでは2つの図を縦に並べます。

誤答時も正解だけでなく、図と「なぜそうなるか」「間違えやすい点」を含む固定解説を表示します。

この学習の流れによって理解しやすくなるかを試用で確認します。

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

- 行動：関心のある業種を入口に、数字の意味を自分で考える。
- 気持ち：「数字はわからない」から「この違いなら説明できる」と感じる。
- 考え方：数字の大小だけでなく、仕事や取引との関係を見る。

### 6-2. 価値を一文で表す

会計初心者が、関心のある業種の架空事例を図で比較し、BSの構成や取引による変化を説明する練習ができるサービスです。

## 7. このアプリで実現すること

### MVPで作る機能

#### ① 業種選択・3択クイズ

- 小売業・製造業・サービス業・おまかせから選びます。
- 選んだ業種の登録済み問題から、重複せずに5問出題します。
- おまかせでは、全業種の問題から出題します。
- 会社同士の比較と、取引前後の比較を扱います。
- ゲストでも利用できます。

必要な理由：自分の仕事や関心を入口に、自分で考える機会を作るためです。

#### ② 正誤判定・図解・解説・結果表示

- 回答後に正誤と固定解説を表示します。
- 会社比較では回答前から2社の図を示し、取引前後の問題では回答後に取引後の図を追加します。
- 5問終了後に正解数と各問の結果を表示します。

必要な理由：正解を知るだけでなく、数字と仕事・取引の関係を理解するためです。

#### ③ ユーザー登録・ログイン・回答履歴・復習

- ユーザー登録・ログイン・ログアウトができます。
- ログイン後の回答をDBに保存し、問題・回答・正誤・日時を確認できます。
- 過去に間違えた問題を選び、1問ずつ復習できます。
- 再挑戦の結果も保存します。

必要な理由：つまずいた問題を後から見返し、理解を確かめるためです。

### 問題の準備と開発範囲

まず3業種×5問、合計15問を目安に、一連の学習体験を試作します。
同じ業種では問題群が同じになるため、試用後に内容の違いや学習上の必要性を踏まえて追加を判断します。

問題は架空の学習用データで作成します。
AIを下書きに使う場合も、数値・正解・解説を確認してから登録します。

業種の自由入力、実在企業のデータ取得・更新、利用中のAI生成は行いません。

### 本リリースに向けた方針

試用結果をもとに問題文・図解・復習の使いやすさを改善します。
追加機能を増やす前に、基本の学習体験を完成させます。

## 8. このアプリの懸念点とその対策

### 問題や解説の正確性

参考資料と数値を照合し、正解が一つに定まること、図と解説が一致することを確認します。

### 業種への固定観念や、簡略例による誤解

事業内容と条件を問題に示し、業種名だけで判断させないようにします。
架空の例であることと、省略した会計上の条件を明記します。

### 答えの丸暗記

正解数だけでなく理由を説明できるかを試用で確認し、異なる着眼点の問題を用意します。

### 回答履歴の管理

他のユーザーの履歴を見られないようにします。
また、問題の修正によって過去の回答との対応が崩れないように管理します。

## 9. 今後の展開・発展の方向性

試用でつまずきの多かった問題や図解を優先して改善します。
業種や問題の追加は、利用者の関心と制作負担を踏まえて判断します。

スマートフォンで読みやすく、回答と復習に迷わない画面を目指します。

## 10. 技術スタック

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails、ERB
- 画面：HTML・CSS・SVG、必要に応じてJavaScript
- DB：PostgreSQL
- 認証：学習済みのRailsの認証方式を基本に検討します
- テスト：主要な処理はRSpec、画面表示や操作性は手動で確認します
- デプロイ：Renderを候補に検討します

### 10-2. 技術選定の理由

学習済みのRailsを中心に、画面・認証・データ保存を一体で実装します。
図解は共通の表示形式を使い、問題ごとの数値を当てはめることで制作負担を抑えます。

問題は確認済みの内容を事前登録し、外部APIに依存しない構成にします。

### 10-3. キャッチアップ不足の懸念

業種に応じた出題、回答履歴、BS図解には追加の調査と学習が必要です。

まず1問の出題・回答・解説表示を試作し、その後、業種選択、5問の出題、ログイン、履歴と復習の順に実装します。

図解の見やすさやスマートフォンでの操作性は、実際の画面で確認します。
問題・数値・解説の正確性は参考資料と照合します。

## 開発環境と起動手順

ここからは実装用の手順です。上記の企画・MVP範囲は変更していません。

- Ruby 3.4.11 / Rails 8.1.4 / PostgreSQL 17
- ERB・CSSによる画面、RSpec・FactoryBotによるテスト
- 現在はTOPページ・ユーザー登録・ログイン・ログアウトまでの開発段階です。
- クイズ・BS図解・回答履歴・復習・公開用15問は未実装です。MVPリリース完了ではありません。
- 公開URLはまだありません。`localhost`のURLは提出に使いません。

### Macで準備する

Homebrewがある環境では、次のコマンドで必要なソフトを用意できます。

```sh
brew install ruby@3.4 postgresql@17
```

Apple SiliconのMacでは、ターミナルを開くたびに次の設定を行います。
システム標準の古いRubyではなく、開発用のRubyを使うための設定です。

```sh
export PATH="/opt/homebrew/opt/ruby@3.4/bin:/opt/homebrew/lib/ruby/gems/3.4.0/bin:/opt/homebrew/opt/postgresql@17/bin:$PATH"
ruby -v
```

`ruby -v`の結果が3.4.11と異なる場合は、Gemfileと異なるバージョンのまま作業せず、使用バージョンを確認してください。

PostgreSQLを起動します。すでに動いている場合は、起動し直す必要はありません。

```sh
pg_ctl -D /opt/homebrew/var/postgresql@17 -l /opt/homebrew/var/postgresql@17/server.log -o '-h 127.0.0.1 -p 5432' start
```

このREADMEがあるフォルダーで次を実行します。

```sh
bundle install
bin/rails db:prepare
bin/rails server -b 127.0.0.1
```

ブラウザで `http://127.0.0.1:3000` を開きます。終了はターミナルで `Control + C` です。
`db:prepare`は、開発用とテスト用の保存場所を用意するコマンドです。本番DBの接続情報を設定した状態で実行しないでください。

### テストとコードの確認

```sh
bundle exec rspec
bin/rubocop
bin/brakeman --quiet --no-pager
bin/bundler-audit
```

RSpecは動作、RuboCopはコードの書き方、Brakemanとbundler-auditはセキュリティ上の既知の問題を確認します。
RSpec実行後は `coverage/index.html` でテストが通ったコードの範囲を確認できます。数値が高くても、すべての動作が正しい保証にはなりません。
GitHub ActionsでもPRの作成・更新時にこれらを実行する設定を用意しています。GitHub上での実行は未確認です。
